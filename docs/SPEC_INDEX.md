## Six requested musical controls

[Six-control specification package](control-specs/README.md) defines phrase placement,
variation distance, change permissions, transition phase, automatic return and
effect activity limits, with shared state/automation/GUI contracts and integration QA.
These are partly implemented; where the code differs from the specs see
[C01-C06 deviations](specs/C01-C06-DEVIATIONS.md).

## Expansion specifications (F01-F12)

The twelve expansion features now have complete implementation-grade specs in
[specs/](specs/README.md): [F01](specs/F01-CONTROLLED-GENERATION.md), [F02](specs/F02-SCENE-MORPHING.md),
[F03](specs/F03-GROOVE-PROTECTION.md), [F04](specs/F04-PERFORMANCE-MODE.md), [F05](specs/F05-PHRASE-EVOLUTION.md),
[F06](specs/F06-POLYRHYTHMIC-LANES.md), [F07](specs/F07-AUDIO-TRIGGERS.md), [F08](specs/F08-VARIATION-HISTORY.md),
[F09](specs/F09-AUDIO-IMPORT-CAPTURE.md), [F10](specs/F10-MULTIBAND.md), [F11](specs/F11-GESTURE-RECORDER.md),
[F12](specs/F12-MIDI-CLAP-PLATFORMS.md). Each describes the feature as implemented in `src/`, the exact parameters, state keys and
real-time behavior, and lists acceptance test IDs with an audited status (EXISTS, PARTIAL, MANUAL, DEFERRED or MISSING) and a reason for anything open. They replace the INCOMPLETE
drafts of [PR #6](https://github.com/djshellshoxxx/GrooveMorph/pull/6) (`spec/groovemorph-expansion-v1`, not merged). TODO items without
another owner are specified in [A04](specs/A04-MIDI-CONFLICT-POLICY.md), [A06](specs/A06-AUTOMATION-IDS-AND-FADE.md),
[A07](specs/A07-ACCESSIBILITY-INPUT.md) and [R01](specs/R01-LICENSING-NOTICES.md).

The planner core (PR #9) is merged and is the base of F01. A spec being complete does
not mean the feature is complete: a feature is done only when every acceptance ID has a test or a recorded reason. Do not classify a
stored seed, undo stack or short history ring as a completed candidate generator, variation-history browser or full capture workflow.
