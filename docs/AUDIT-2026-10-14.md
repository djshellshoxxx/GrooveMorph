# Code audit, 2026-10-14

Three independent read-only audits (timing and audio callback; GUI completeness; state, serialization and model code)
were run on branch `claude/affectionate-hopper-5naq7k` after user feedback that a 140 BPM loop played too fast.
Findings were verified against the code before fixing. Nothing here was validated in a DAW or with audio hardware.

## Root cause of the reported tempo problem
1. In Standalone the musical position was recomputed from the total sample count times the *current* tempo, so changing the
   tempo made the position jump. Fixed: the grid origin is re-based on every tempo or meter change.
2. An imported loop's speed is `file length / (beats x beat length)`, and the beat count came from a "bars" menu (default 2)
   that had no relation to the file. Loops with a tail or a different bar count therefore played too fast or slow whenever the
   tempo was not the one that happened to match. Fixed: the loop is defined by its own tempo (BPM box, or Auto bars), the
   tempo is reported, and "Set tempo to loop" exists. Verified: a 140 BPM loop plays at exactly 1.00x at 140 BPM and 0.857x at 120.
3. Imported files were not resampled to the device rate. Fixed.

## Found but NOT fixed (open items)
Audio/timing: host `timeInSamples`-based modes still derive position from samples x current tempo (tempo automation);
AutoReturn/phrase index use absolute bar positions in those modes; loop/demo ignore later meter changes and the demo
assumes 4 beats per bar; a failed `loopSource.load` discards a finished capture; timer services never start if the processor is
created before a MessageManager exists; a held MIDI note can stick after All-Notes-Off; host phrase origin assumes a constant
meter from ppq 0; a tempo change during a capture is not detected; sample rates below 8 kHz are still rejected.
State/model: no migration framework (only v1 exists); evolution settings and gestures are not saved; `beginAudition` while a
preview has unsaved edits drops them; loaded event lanes are not re-validated for overlaps; `logLerp` uses `log2/exp2`
(possible 1 ulp libm differences between platforms for generated candidates); several behaviours lack tests (PlacementEvaluator
block-split and polyrhythm edge cases, GestureLane in isolation, MIDI program change).
GUI: empty "Use event lanes" silences everything without a warning; cadence offset is not clamped to Every-N; evolution restarts
on every tweak; unsaved state (evolution, gestures, generator, macros, source) has no cue beyond tooltips; gesture target change
clears the lane without confirmation; the edit-scene combo is disabled during a preview without explanation; stale Scene-tab
messages; events cannot be created by keyboard; the bank seed and the evolution seed have no UI; minimum editor size 1230x700.
