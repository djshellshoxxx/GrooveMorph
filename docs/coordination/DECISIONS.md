# Decisions

- **Scene control state lives in `VariationSettings::control`** (placement, lane, permissions, activity). Trivially copyable, so the existing SceneSnapshot handoff to the audio thread is unchanged.
- **Scene file format stays `v1`.** Control keys are written only when non-default and ignored by older builds; old files load with inert defaults. No migration step is needed.
- **Placement gates operation `enabled`/`depth` per slice; the RhythmEngine is unmodified.** The renderer splits at the next placement boundary (nearest sample, >= 1 sample). Consequence: event edges are sample-accurate but each operation keeps its shared beat phase (the spec's LegacyUniform shape); per-event phase restart is not implemented.
- **Ticks are 1/960 of a meter beat, not of a quarter note** (spec uses quarter ticks). Equivalent for x/4 meters; simpler and exact for every supported subdivision. Revisit if per-event anchors are added.
- **Host Variation parameter = requested variation.** The message thread realigns it to the sounding variation when nothing is pending and the audio thread has read the current value; echo writes are ignored by the audio thread. Never written from the audio thread.
- **Locks are enforced after generation** so random draws never depend on locks (spec C03).
- **Generator previews through the existing AuditionSession**, sourced from the stored scene, so nothing is committed until Apply.
- **Morph/auto-return are APVTS parameters** (IDs appended, never reused); locks, placement, events are scene state.
- **Auto-return requests a NextBar switch one bar early** so the existing Scheduler lands it on the bar line.
- **Demo loop is not a parameter and not saved.** It overwrites the input in the callback while the transport is playing.
- **Per-event cycle restart is an engine phase offset** (`RhythmTiming::phaseOffsetBeats`, zeros = legacy grid, bit-identical). The evaluator supplies the absolute beat of the active event onset; the engine measures each operation's slice grid from it.
- **Polyrhythm = per-lane loop rings** in the evaluator (events repeat every `loopBeats[op]` beats); no second clock or Scheduler.
- **Loop stretch to host tempo is opt-in** (`loopStretch` parameter, default off): a background WSOLA render replaces the varispeed buffer through the same reader-flag handoff; off is bit-identical to the beat-locked varispeed.
- **Loop playback is beat-locked, not stretched.** `LoopSource` maps the timeline beat to a file position; capture starts on a bar line and records exactly N bars.
- **Loop audio is saved in the project state** (W4, `LoopAudio` child: versioned, CRC-checked, 16-bit PCM + Rice-coded blob, <= 20 s / 10 MiB; the plugin state limit is 16 MiB). Old projects without it load unchanged and keep the session loop. The source mode is saved only with a loop. The bounded generator history is saved locally in the user's application-data directory, with source-scene snapshots and generator settings; it is not project state. Gesture-lane bins and target, and phrase-evolution settings, are saved in the project state (`Gesture`/`Evolution` child trees; absent in older projects and then default). Evolution is restored as saved (including on/off) with a fresh step counter; its seed is fixed (0x47524F4F56), not saved, and has no UI.
- **Locks apply to every edit path** (manual, preview, history recall, whole-scene operations); lock configuration itself stays editable.
- **Loop-service handoff** uses a reader-flag handshake plus a mutex against `prepareToPlay`; the audio thread never takes a lock.
- **C04 phase is scene content, not an APVTS parameter** (deviation from the spec text): `PhaseConfig{policy, offsetBeats}` is stored per scene as optional v1 keys (`phase.policy`, `phase.offset`), so it undoes, copies and morphs with the scene and needs no new host parameters. The processor keeps one audio-thread `phaseShiftBeats` (pattern position = transport position + shift), recomputed at the actual switch sample (or on "Restart scene now") and cleared on a seek/loop. Phrase cadence (Every/Offset) and bar-start protection stay on the global grid via the optional `globalBeats` argument of `evaluate()`. The per-scene smoothing time of the spec is NOT implemented: pattern jumps use the engine's existing fixed cross-fade taps.
- **Protected regions live in `PlacementConfig`** (max 4, circular on the pattern-local phrase), covered by the placement lock; **per-event locks** are a `LaneEvent::locked` flag handled by `enforcePermissions` and Reduce/Scale alongside the per-operation Events lock. Both are optional v1 keys.
- **Band crossover slope option** (`bandSlope`, appended parameter, default 6 dB/oct). 12 dB/oct makes the band sent to the effects a 2nd-order Butterworth (TPT state-variable filter); the bypassed band is its exact complement (`in - effected`), so any split is bit-exact when the effects change nothing. Measured offline: low/high rolloff of the effected band -24 dB at two octaves versus -12 dB for the 6 dB option. A subtractive complement keeps 6 dB/oct on the other side, so this is not a Linkwitz-Riley split.
- **Overlap checks use the lane's own loop ring** (`loopBeats[op]`); Reduce now also unrolls each lane's loop ring (W3, see the loop-aware Reduce entry below).
- **Supported sample rates are 8 kHz to 384 kHz for timing; engine/loop memory (about 235 MB of buffers at 384 kHz) and audio at 384 kHz are not tested** (limit raised from 192 kHz by the visual-feedback branch merge on 2026-10-14; the portable timing contract in `PhraseClock` is the reference).
- **Plugin-originated parameter writes** (Variation realignment, MIDI macros) are bracketed with `beginChangeGesture`/`endChangeGesture`. Gesture playback (F11) is deliberately NOT bracketed (a plugin-driven stream, not a user touch) and writes only when the sampled value differs from the parameter by more than 1/512 (`GestureLane::worthWriting`); corrected in the A1 audit, the earlier text said it was bracketed.
- **CLAP and release packaging (N06).** CLAP is built through `free-audio/clap-juce-extensions` pinned to a commit (`cmake/GrooveMorphPins.cmake`), default ON via `GROOVEMORPH_ENABLE_CLAP`, no processor changes. The `VERSION` file is the single version source (tag = `v` + VERSION; CMake `project()`/JUCE use the numeric part; `groovemorph/Version.h` carries the full string). Beta releases come only from `.github/workflows/beta-release.yml` (tags `v*-beta*` or manual dispatch); the alpha workflows are superseded and their `[publish-alpha]` commit-message trigger is not reused. See `docs/specs/N06-CLAP-AND-RELEASE.md`.

## W3 (dsp/control completions) decisions and deviations

Specs: `docs/specs/W3-*.md`.

- **C04 smoothing is scene data, not an APVTS parameter** (same deviation as the phase policy): optional v1 key `phase.smooth`, written only when non-zero, bounded 0..250 ms (NaN becomes 0). 0 means the engine default (3 ms) and is bit-identical to before (EngineGoldenTests, including an explicit 3 ms run). A requested fade longer than the history allows is limited so at most two cross-fade taps stay live.
- **C04 capture at request time:** `LaunchPhase` holds the destination's `PhaseConfig` (policy, offset, smoothing) when the request is made; the switch uses that copy. A newer request replaces it; a mismatching variation falls back to the live config.
- **Dry return is an appended choice, value 5** of `autoReturnTarget` (spec fixes Dry = 5). The choice list got longer; a host that stores the normalised value sees it rescale (indices 0-4 keep their meaning once the host re-reads the list). The Dry boundary cuts the audio segment and forces the wet amount to 0 through the engine's own ramp; any scene request, cancel, seek or rewind clears it.
- **Crossover topology is a new appended parameter `bandTopology`** (Classic / LR 12 / LR 24). `bandSlope` keeps its meaning and is ignored by LR. Legacy projects have no value and load as Classic. LR2 uses 1-pole cascades (high band inverted), LR4 uses cascaded TPT Butterworth sections, in double precision; cutoff glides over 5 ms; the "unchanged band is exact dry" shortcut is smoothed with a short blend so it does not click.
- **Capacity:** 256 events per lane (`uint16_t count`, widened per the integrator), 8 protected regions. Fixed arrays; `SceneSnapshot` is about 25 KB and is copied under the existing try-lock only when a scene changes. Serialization needed no format change.
- **Loop-aware Reduce:** spacing, coverage and concurrency use each lane's loop ring unrolled over the phrase; a looping lane whose own repeats violate spacing counts as a conflict.
- **Morph (F02):** discrete fields (enabled flags, policy, window, subdivision) come from `a` while the amount is below 0.5, else from `b`; depths, slices, offsets and placement numbers interpolate; protected regions are the union (capped at 8); lane events are matched by (operation, onset, duration) and blended, unmatched events scale their depth by their side's weight, overlap is resolved for the dominant side, capped at 256. Locks and permissions follow the dominant side. Pure and deterministic; the processor rebuilds the result only when (scene, target, amount, scene version, phrase length) changes.
- **Input sanitizing:** the whole buffer is sanitized at the top of `process()` (before any early return, also when bypassed) and again at the output; non-finite samples become exactly 0. Finite samples, including denormals, are untouched. The count is exposed for tests.
- **Timer and evolution (KNOWN-ISSUES #4):** `ServiceTimer` replaces the `juce::Timer` base (shared core, mutex, lazy start, detach waits for an in-flight tick). The message thread prepares the NEXT evolution step and publishes it in the scene snapshot; the audio thread applies it on the first sample of a qualifying phrase (segments are cut at the boundary) and reports the applied step. Residual limit: an edit published less than ~50 ms before a boundary may apply the previous plan's step for one phrase.
