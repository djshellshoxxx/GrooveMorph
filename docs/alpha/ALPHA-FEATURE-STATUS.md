# Alpha feature status

Windows x64 Standalone alpha (exploratory; not a beta, not production). Status words are used
strictly: *Complete and tested* / *Implemented, partially tested* / *Partially implemented* /
*GUI-only / not functional* / *Specification only* / *Not implemented* / *Blocked by dependency*.
"Tested" means automated tests on Linux (GCC and Clang, ASan/UBSan for the portable core) and Windows CI.
No feature was tested in a DAW, with audio hardware, or by listening.

The Generator tab keeps a bounded history file under the user's application-data directory. It stores source-scene snapshots so recalled candidates can be reconstructed after the project or editor closes. This file is local computer state; it does not travel with the DAW project.

Deviations from `docs/control-specs`: events use meter-beat ticks (960/beat) instead of quarter-note ticks; scene-control
keys are optional keys in format v1 rather than a v2 header; capacity is 32 events per scene (spec: 256); at most 4 protected regions (spec: 8); C04 phase is scene data, not APVTS parameters, and has no per-scene smoothing time; no "Dry" auto-return target. F01-F12 have no in-repo specification (the drafts are in unmerged PR #6), so their status reflects the author's own tests. Most acceptance-test IDs in the C01-C06 specs have no test by that ID (traceable: C01-T01/T03 analogues, C04-T01/T02); the 'Needs' columns above are the honest gap list.
